Replies stream token-by-token and run until the model finishes (its end-of-text token or a new turn), so long answers aren’t cut off. For a real answer (e.g. code) pick a real model — Qwen2.5 writes working C; the toy models (marvin/instruct/sft) only know their tiny training data. Sampling is fixed (temp 0.8 / top-k 40 / top-p 0.95).
Upload any image (downscaled to ≤16×16). Reconstruct rebuilds it; Caption teaches a caption then reproduces it; Text→Img teaches “prompt → this image”, then regenerates the image from the prompt (teach-then-reproduce, not zero-shot text-to-image). Toy-scale by design.
Upload a 16-bit PCM WAV (≤256 samples). Reconstruct rebuilds it; Caption teaches + reproduces a caption; Text→Aud teaches “prompt → this clip”, then regenerates the audio from the prompt (teach-then-reproduce). Toy-scale.
Upload a short video — frames are extracted (needs ffmpeg on PATH), embedded, and a tiny model is taught your caption then reproduces it. This is teach-then-reproduce: the multimodal front-end is untrained, so it proves the pipeline runs on your real frames end-to-end — not a real captioner. A frames preview (GIF) is shown.
